eBPF runtime security for Kubernetes

A sensor that stays on guard when someone tries to blind it.

Tephra watches every pod from the kernel, alerts on what attackers do, and can refuse it. Kill it, freeze it or flood it, and the kernel keeps refusing the moves that come next.

What happens when an attacker kills the sensor

The first thing an attacker on a node does is blind the sensor. Step through it.

The kill is recorded

A signal to the agent goes to a ring buffer that nothing else writes to, so a flood cannot push it out. The next agent raises R030 with the sender and its pod.

lab, 5.15, 26 Nov
# E19: an attacker in a pod that sees the node's processes
$ kill -9 16659

R030 critical  Signal sent to the Tephra agent
     SIGKILL from /bin/sh (sh -s)
     pod: tephra-e19-838ddf/victim

The kernel keeps recording

The detection programs and their buffer are pinned in the kernel. While no agent runs they keep recording, and the next agent reads what happened meanwhile. A stop by Kubernetes removes the pins: an upgrade leaves nothing behind.

lab, 5.15, 26 Nov
# agent killed at 12:49:35; the read, 5 s later
$ dd if=/etc/shadow of=/dev/null

R005 high  /etc/shadow opened  12:49:40
     /bin/dd  pod: tephra-e19-838ddf/victim

The next move is refused

Once the agent is gone, stopped or silent for 12 seconds, the kernel refuses a short list of moves in every pod: reading /etc/shadow, writing ld.so.preload or authorized_keys, loading a module, mounting, ptrace, running a deleted binary. Each refusal raises R038 when the agent is back.

lab, 5.15, 26 Nov
# E07: kill the agent, then at once
$ cat /etc/shadow

R038 critical  Action refused while the sensor was blind
     file_read /etc/shadow  by /bin/cat  denied
     pod: tephra-e07-eeca6c/victim

A flood leaves counts, not gaps

Under pressure the kernel sends the first open of each file by each program in each pod, and counts the rest. A flood can no longer push the one record that matters out of the buffer.

kernel test, 5.15
# 1,000 opens of one file with the buffer half full
records sent   56
counted        545 + 399
lost           0
Measured, not claimed

Get started

One Helm chart

Detection, blind mode and the dashboards. Enforcement stays off until you turn it on. From v0.2.0 the chart is also an OCI package on GHCR.

git clone https://github.com/tephrasec/tephra
cd tephra
helm install tephra deploy/helm/tephra \
  -n tephra --create-namespace
